# 改造方案：拼多多客服 → 视频号 + Dify 智能客服

## 一、背景与目标

当前系统是一个**拼多多店铺桌面客服**（PyQt6 + 自定义 Agent + SQLite 知识库），需要改造为：
- **渠道**：视频号私信/留言（替换拼多多 WebSocket）
- **引擎**：Dify 对话应用（替换内置 CustomerAgent 的 LLM 循环）
- **知识库**：保留本地 SQLite，调用 Dify 前做预检索注入

## 二、现状架构（改造前）

```
[拼多多 WebSocket] → PDDChannel → Context → Queue → Consumer → Handler Chain
                                                              ├─ KeywordHandler ──→ SendMessage(PDD API)
                                                              └─ AIReplyHandler ──→ CustomerAgent(OpenAI SDK)
                                                                                   └─ tools: KnowledgeService(SQLite) + SendMessage(PDD API)
```

**核心 PDD 硬编码点（必须改造）：**

| 位置 | 硬编码内容 |
|------|-----------|
| `ui/auto_reply/threads.py:67` | `from Channel.pinduoduo.pdd_channel import PDDChannel` |
| `Message/handlers/ai_handler.py:104` | `from Channel.pinduoduo.utils.API.send_message import SendMessage` |
| `Message/handlers/keyword_handler.py:9` | 同上 + `send_text`/`move_conversation`/`getAssignCsList` |
| `Agent/CustomerAgent/tools/send_goods_link.py` | PDD 发货链接 |
| `Agent/CustomerAgent/tools/move_conversation.py` | PDD 转人工 |
| `Agent/CustomerAgent/tools/get_product_list.py` | PDD ProductManager API |
| `bridge/context.py` | 只有 `PinduoduoKwargs`，无微信 Kwargs |

## 三、目标架构（改造后）

```
[视频号 HTTP Polling] → WeChatVideoChannel → Context → Queue → Consumer → Handler Chain
                                                                     ├─ KeywordHandler ──→ channel.send_reply() (多态)
                                                                     └─ AIReplyHandler ──→ DifyBot ──→ Dify API (HTTP)
                                                                                         │
                                                                                         ├─ 预检索: KnowledgeService.search_knowledge()
                                                                                         └─ 注入知识到 Dify query
```

### 阶段 2：新建视频号渠道包 —— `Channel/wechat_video/`

**目标**：创建与 PDD 平行的视频号渠道实现，用 HTTP 轮询替代 WebSocket。

**新建文件结构：**

```
Channel/wechat_video/
├── __init__.py
├── wechat_video_channel.py     # 主类，组合 Mixin
├── core/
│   ├── __init__.py
│   ├── wechat_config.py        # 视频号 API 配置（appid, secret, 轮询间隔等）
│   ├── wechat_connection.py    # HTTP 连接 + access_token 管理
│   ├── wechat_message_handler.py  # 留言解析 → Context 转换
│   └── wechat_lifecycle.py     # 轮询循环（替代 WebSocket 长连接）
└── utils/
    ├── __init__.py
    └── send_message.py         # 视频号消息发送（回复留言/私信）
```

**关键技术差异 vs PDD：**

| 维度 | PDD | 视频号 |
|------|-----|--------|
| 认证方式 | Cookie (Web 扫码登录) | OAuth2 access_token（appid + secret） |
| 连接方式 | WebSocket 长连接 | HTTP 轮询（定时 GET 新留言列表） |
| 消息格式 | 自定义 JSON | 微信标准 JSON |
| 重连机制 | WebSocket 重连 + 指数退避 | token 过期自动刷新 + 请求重试 |
| 凭证存储 | cookies（加密 JSON） | access_token + refresh_token |

**核心实现要点：**

- `wechat_connection.py`：封装 access_token 获取/缓存/自动刷新（token 有效期 2h），复用 `BaseRequest` 的重试机制
- `wechat_message_handler.py`：微信留言 JSON → `ChatMessage` → `Context`（用 `WechatVideoKwargs`），判断消息类型（评论/私信/图片）
- `wechat_lifecycle.py`：`while not stop_event:` 循环，每 N 秒（建议 5-10s）拉取新消息，去重后放入 Queue
- `wechat_video_channel.py`：组合 Mixin + Channel 基类，实现 `send_text`/`transfer_to_human`

**注意**：微信视频号私信/留言的具体 API 端点取决于你的账号类型（普通视频号 vs 视频号小店），以下是通用模式：

```
# 获取 access_token
GET https://api.weixin.qq.com/cgi-bin/token?grant_type=client_credential&appid=APPID&secret=APPSECRET

# 拉取留言列表（具体端点以微信开放平台文档为准）
POST https://api.weixin.qq.com/channels/ec/comment/list

# 回复留言
POST https://api.weixin.qq.com/channels/ec/comment/reply

# 发送客服消息（私信）
POST https://api.weixin.qq.com/cgi-bin/message/custom/send
```

### 阶段 3：新建 DifyBot —— 替换 CustomerAgent

**目标**：创建实现 `Bot` 接口的 Dify 智能体，本地预检索知识库后调用 Dify。

**3.1 新建包：`Agent/DifyAgent/`**

```
Agent/DifyAgent/
├── __init__.py
├── dify_bot.py          # DifyBot(Bot) 核心实现
└── dify_config.py       # Dify 配置（api_key, base_url, 检索策略）
```

**3.2 `dify_bot.py` 核心逻辑：**

```python
class DifyBot(Bot):
    async def async_reply(self, query: str, context: Context = None) -> Reply:
        # 1. 提取 shop_id（从 context.kwargs）
        # 2. 本地预检索知识库
        knowledge = knowledge_service.search_knowledge(shop_id=shop_id, query=query)
        # 3. 构造富化 query
        enriched_query = f"用户问题：{query}\n\n相关知识：\n{knowledge}\n\n请基于以上知识回答。"
        # 4. 调用 Dify API（HTTP POST）
        response = await self._call_dify(
            query=enriched_query,
            user_id=context.kwargs.openid,
            inputs={"shop_id": shop_id}
        )
        # 5. 返回
        return Reply(ReplyType.TEXT, response["answer"])
```

**3.3 Dify API 调用格式：**

```
POST {DIFY_BASE_URL}/v1/chat-messages
Authorization: Bearer {DIFY_API_KEY}
{
  "inputs": {"shop_id": "xxx"},
  "query": "用户问题 + 预检索知识",
  "response_mode": "blocking",
  "conversation_id": "",
  "user": "{openid}"
}
```

**3.4 `config.json` 新增 Dify 配置段：**

```json
{
  "dify": {
    "api_key": "app-xxxxxxxxxxxxx",
    "base_url": "https://your-dify-instance.com",
    "use_local_knowledge": true
  }
}
```

**3.5 DI 容器改造 `core/di_container.py`：**

```python
# 根据配置决定用哪个 Bot
bot_type = config.get("bot_type", "dify")  # "dify" 或 "builtin"
if bot_type == "dify":
    container.register(Bot, DifyBot, DIContainer.SINGLETON)
else:
    container.register(Bot, CustomerAgent, DIContainer.SINGLETON)
```

## 六、验证方案

1. **配置验证**：启动应用 → 设置页填入 Dify API Key + 微信 appid/secret → 保存 → 检查 `config.json`
2. **渠道验证**：添加视频号账号 → 点击"上线" → 日志确认 access_token 获取成功 → 轮询开始
3. **消息流程验证**：在视频号发留言 → 日志确认消息解析为 Context → 进入队列 → Handler 处理
4. **知识检索验证**：发产品相关问题 → 日志确认 `KnowledgeService.search_knowledge()` 被调用
5. **Dify 回复验证**：Dify 返回回答 → 日志确认 → 视频号留言被成功回复
6. **关键词转人工验证**：发含"转人工"的消息 → KeywordHandler → channel.transfer_to_human()

## 七、注意事项

1. **视频号 API 具体端点**需要根据实际的视频号类型和微信开放平台权限确认，方案中的 API URL 为通用模版，实现时对照微信文档调整。
2. **`send_goods_link`、`get_product_list`、`move_conversation`** 这三个 PDD 专属工具在 Dify 模式下不再需要。
3. **`get_product_knowledge` 和 `search_customer_service_knowledge`** 的查询能力由阶段 3 的预检索逻辑替代。
4. **建议保留** `CustomerAgent` 代码不删除，通过配置开关 `bot_type` 切换，便于回退和调试。
5. 视频号的消息量通常小于拼多多店铺，5-10s 的轮询间隔足够，无需 WebSocket 长连接。
